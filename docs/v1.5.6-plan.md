# V1.5.6 behavior and implementation notes

The owner authorised implementation and publication on 2026-11-16. The release retains native Rust/FLTK widgets and event-driven idle behavior. No automated, interactive or installation tests, app launches or screen control were performed. See [release notes](../RELEASE_NOTES.md) for user-facing changes.

## Event dispatch and lifecycle

CFLTK's default superclass-first handling executes both native and custom handlers. Run the custom window/text handler first and consume handled events, allowing normal native handling only for unhandled events. This avoids multiplying paste and keyboard actions without content-based deduplication that would reject intentional repeated pastes.

The macOS bridge subclasses the existing FLTK delegate at runtime and overrides native terminate/reopen callbacks; inherited file-open handling remains intact. Termination queues QuitAll and returns NSTerminateLater while the Rust loop preserves work and handles cancellation/failure. It replies to AppKit only after successful saving/shutdown, or cancels termination on a user cancellation/persistence error. A successful exit stops sharing and leaves the event loop regardless of background mode. Dock reopening routes to ShowWindows. Dirty documents require save/discard/cancel if protected session recovery is unavailable.

V1.5.6 IPC handoff requires UI confirmation after revealing the window; legacy instances retain their existing handoff protocol. Retries carry a stable request identifier so delayed delivery does not open documents repeatedly. A quitting/nonresponsive instance does not silently acknowledge reopening; startup can retry the OS lock after bounded backoff. The presence of session.lock alone never blocks startup. Available profiles/caches/identities are not cleared. The exact originally reported post-Force-Quit failure remains unconfirmed without user runtime evidence; diagnostics now identify the affected paths.

## Local editing and organisation

Tab indices remain stable; only presentation order changes: pinned tabs first, then named groups, then ungrouped tabs. Group names are bounded, control characters removed and existing spelling reused for case-insensitive matches. Local session state stores pin/group/display preferences without altering document files or network revisions.

Cleanup strips only explicitly selected trailing spaces/tabs and/or repeated empty lines. Plain text uses native atomic edit undo; mixed content retains before/after text for the cleanup action and derives image offsets from unchanged markers. Encoded image payloads are not copied into cleanup history. Loading/replacing a document clears the cleanup context. Invisible glyphs are clipped overlays with bounded visible-range rendering, never document characters.

## Key-store migration

Password-to-system conversion uses the successfully unlocked existing master key. Before changing credentials/header state, persist and authenticate security/vault.password-backup.json, which contains a password-wrapped key, not a plaintext key. Store/read back the OS credential, atomically replace vault.json and recheck the saved header/master. On confirmation failure, restore the original password header; keep the backup for recovery. No new document key, device identity or pairing is generated.

If OS retrieval later fails, the preserved password header is eligible only when its profile ID and authenticated canary match the current header. It unlocks the current session without silently changing the system-protected header. Portable mode keeps its password requirement. A user who keeps password mode or encounters an unavailable key store can retry from Security settings instead of receiving the conversion offer on every start.

Linux tries Secret Service storage and falls back to the existing KDE Wallet 6/5 D-Bus API. Native wallet open/access approvals remain OS decisions. A wallet session is reused for the application lifetime so storing and verifying a key does not repeatedly open/close the wallet. KDE Wallet is not a plaintext fallback. The profile records the backend and never regenerates a missing key. Flatpak permissions are limited to the named credential services. Interface reference: [KDE Wallet D-Bus API](https://github.com/KDE/kwallet/blob/v6.10.0/src/api/KWallet/org.kde.KWallet.xml). No new runtime dependencies were introduced.

## Log and sync semantics

Sync now skips the writing delay and retries communication; it does not overwrite concurrent branches or bypass trust/consent. A reachable peer is not necessarily fully synchronised. Friendly logs explain the operation and its limits; technical mode includes the existing bounded protocol records. Filtered and pseudonymised exports remain separate and contain no document bodies or private keys.
