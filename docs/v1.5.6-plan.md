## macOS lifecycle source findings (not runtime-verified)

The bundled FLTK Cocoa applicationShouldTerminate handler dispatches FL_CLOSE to windows and cancels termination if a window remains shown. EditorTool window callbacks enqueue CloseWindow asynchronously. CloseWindow can hide windows and keep the process alive when background mode is enabled. The native quit path does not explicitly route to EditorTool's existing QuitAll action, which persists/flushes the session, stops sharing and requests event-loop exit. This is a plausible cause of the Cmd+Q/background behavior, not proof of the later restart failure.

Route native application quit, including the menu/Dock request, through an application-wide shutdown path. Closing a window and quitting the application must retain separate behavior. Preserve dirty work and honor cancellation/persistence failure before accepting a graceful exit; quitting explicitly must override keep-in-background preferences. Keep settings/auxiliary windows and multiple editor windows in scope.

Inspect Dock reopen behavior and startup after forced termination. The current file-open callback ignores null paths and only forwards document-open requests. The profile uses an OS file lock, not merely existence of session.lock; do not delete caches, identities or a lock owned by a live process as a workaround. Forced termination cannot guarantee saving edits beyond the last completed durable write. Diagnose the startup failure before claiming it repaired.
